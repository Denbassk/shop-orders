# Команды и конвейер

Всё через `python matrix.py <команда>` или меню `МАТРИЦА.bat`.

| Команда | Меню | Что делает |
|---|---|---|
| `ui` | 1 | окно новинок на localhost:8765 |
| `sync` | 2 | полный пересчёт матрицы |
| `new` | 3 | пересканировать новинки (find_new_items) |
| `diff` | 4 | снапшот матрицы + журнал изменений |
| `log` | 5 | журнал: что добавлено/выведено за 90 дней |
| `barcodes` | 6 | скан осиротевших ШК (dry-run) |
| `merge` | 7 | то же с записью пар и правкой ШК |
| `audit` | 8 | интерактивный аудит ШК |
| `profit` / `prices` / `coverage` / `status` | 9–12 | отдельные колонки |
| `check` | 13 | проверка структуры таблицы (ничего не меняет) |
| `totals` | 14 | пересчёт строк ИТОГО |

## Порядок в `sync` (важен именно такой)

```
diff → barcodes → profit → prices → coverage → status → totals
```

- `diff` **первым**: фиксирует, что пользователь добавил/удалил руками,
  до пересчёта. Иначе изменения потеряются.
- `barcodes` — только предупреждение, ничего не пишет.
- `status` после profit/prices/coverage: считается по ним.
- `totals` **последним**: ИТОГО считает новинки/вывод по ЦВЕТУ ЗАЛИВКИ
  строки, а красит её `status_update`. См. `mem:apps_script`.

Падение `diff` или `barcodes` не критично — идём дальше. Падение
`profit`/`prices`/`coverage` останавливает конвейер, чтобы не записать
половину данных.

`new` в конвейер не входит: это отдельная задача, а не пересчёт цифр.

## Ключевые пороги (bc_common.py)

```python
MEMORANDUM_DAYS = 120        # сколько дней товар считается новинкой
OPT_STORE = "Полевая-Магазин"
OPT_MAX_STORES = 3           # опт: есть Полевая и точек не больше
PROFIT_START_DATE = "2026-01-01"
TECH_NAME_RULES = [...]      # правила «это техтовар/расходка»
EXCLUDE_STORES_SALES         # склады и просрочка — не точки продажи
EXCLUDE_STORES_INCOMING      # тут РЦ ОСТАВЛЕН
```

**Списки магазинов разные по смыслу, не объединять!**
В продажах `Полевая-Склад` (РЦ) исключён — не точка продажи.
В приходах он ОСТАВЛЕН — новинка приезжает на РЦ раньше, чем в магазины,
и ловить её надо там. Однажды «привёл к единому виду» и потерял 50 позиций
из детекта. Согласовано только написание просрочки (`Магазини-`/`Магазины-`).

## Классификация новинок (bc_common.classify_item)

Порядок: ТЕХ > ОПТ > НОВИНКА > В обігу.

- **ТЕХ** — комплектующие хот-догов, наполнители кофемашины, хозрасходка.
  Правила в `TECH_NAME_RULES`: префикс `Фаст-Фуд`, `(1кг)` в конце,
  `Баріста`, `Якобз Цукор`, ганчірка/швабра, паперовий пакет,
  цінник/термопапір, підставка/щипці/листівка/наліпка/інструкція.
  Не задевает розницу: «Кава Якобз 3в1 18гр» и «Якобз Кава 120г» остаются.
- **ОПТ** — среди точек за 90 дней есть `Полевая-Магазин` и всего точек ≤3.
  Полевая — опт, заказы идут только туда, в матрицу такое не вносится.
- **НОВИНКА** — первый приход ≤120 дней.

Сортировка активного списка: новинки сверху, потом по покрытию, потом по
свежести прихода. Прибыль — последний ключ: у настоящей новинки её мало.

## Память решений

Таблица `item_lifecycle_decisions`. Статусы: `Додати`, `Додано`,
`Не брати`, `Думаю`, `Тех.товар`, `Опт (Полевая)`, `Виведений`.

- `Додано`, `Тех.товар`, `Опт (Полевая)` — окончательные, позиция не всплывает.
- `Думаю` и `Додати` остаются в работе (`Додати` = «беру», но ещё не добавлено).
- `Виведений` — показывается с пометкой «Раніше виведено», НЕ прячется.
- Отклонённая позиция возвращается сама, если выручка 90д выросла
  в `RESURFACE_FACTOR` (2×) и превысила `RESURFACE_MIN_REVENUE` (500 грн).
  В «Коментар» пишется `⚠️ ПЕРЕГЛЯНУТИ: ... ‖ <комментарий пользователя>`,
  служебная часть до `‖` при следующем чтении отбрасывается.
